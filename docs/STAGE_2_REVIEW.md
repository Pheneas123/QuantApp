## Mathematical and technical verification

Every explanation and all 480 choices were reviewed under the actual stated assumptions. Automated checks distinguish simple choice identity from mathematical equivalence; passing validation alone does not prove unique correctness. The ledger explains why each alternative fails, and the numerical tests connect computed quantities to actual answer strings, rather than only checking a stored index.

Independent calculations include finite enumeration of sampling without replacement and distinct occupancy; conditional bit sample spaces; total variance; confidence coverage and binomial tails; OLS projection algebra; numerical quadrature for the singular positive kernel and logarithmic DCT example; biased random-walk second moments; CTMC forward-equation verification; Itô drift cancellation and the backward heat PDE; ridge linear-system solves; preconditioned spectra; Schur complements; finite-difference softmax and policy gradients; unequal-microbatch mean gradients; and pairwise tie-aware AUC. Conceptual, infinite-measure and filtration arguments were reviewed separately; finite simulations do not certify such claims.

Primary contract checks:

- C++20 rules use [WG21 N4861](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2020/n4861.pdf), particularly class construction, forwarding, shared ownership, sequence-container preconditions and vector capacity. Out-of-size indexing violates the element-access contract; allocating capacity does not create elements. No UB example was executed. The move-only `std::function` question explicitly uses GCC/libstdc++ 16: the C++20 text states a CopyConstructible precondition, while this toolchain diagnoses the attempted target. The [current constructor contract](https://eel.is/c++draft/func.wrap.func.con) also makes copy-constructibility explicit. Compiler acceptance is kept separate from runtime validity.
- Python checks use the documented [context-manager protocol](https://docs.python.org/3/reference/datamodel.html#object.__exit__), [deep-copy memo](https://docs.python.org/3/library/copy.html) and [live mutable-sequence iteration](https://docs.python.org/3/library/stdtypes.html#common-sequence-operations). Only exception class/underlying unhashability is asserted; exact diagnostic wording varies by Python version.
- NumPy contracts use [advanced versus basic indexing](https://numpy.org/doc/stable/user/basics.indexing.html) and [unbuffered repeated-index updates](https://numpy.org/doc/stable/reference/generated/numpy.ufunc.at.html). Output and shapes were executed with NumPy 2.5.3/Python 3.14.7.
- Adam follows [Algorithm 1 in the original paper](https://arxiv.org/pdf/1412.6980). The ε=0 example has a nonzero denominator and makes no universal convergence claim.
- Gaussian posterior identities were checked against [GPML chapter 2, equations 2.23–2.24](https://gaussianprocess.org/gpml/chapters/RW2.pdf), then separately against small covariance linear systems.
- Framework contracts were checked against PyTorch’s official [CrossEntropyLoss](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html), [Conv2d](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Conv2d.html) and [Dropout](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Dropout.html) documentation. **PyTorch is not installed and was not executed.** Equivalent mathematical loss weighting, gradients and shapes were checked independently; no heavy framework was installed. The script conditionally executes the relevant framework examples when available.

`test:stage2-code` passes six Python/NumPy output checks, a TypeError check, nine C++20 output checks, two expected compilation failures, a repaired erase loop, one syntax-only UB example and the independent scientific checks. GCC is 16.2.1 with `-std=c++20 -Wall -Wextra -pedantic-errors`. The original `test:code` and `test:learning-code` checks also pass, preserving earlier evidence.

## Significant corrections and overlap findings

- Required n≥2 in the exponential lower-bound item so omitting n cannot produce an identical offered expression. Its 95% tail inversion was independently checked.
- Made Gamma–Poisson counts explicitly independent **conditional on λ**; their prior predictive counts need not be independent.
- Restricted the reciprocal diffusion to positive volatility and used explicit nonzero/nonunit multiplicative noise in the conversion example. Brownian-bridge quadratic variation uses dyadic deterministic partitions and an almost-sure pathwise statement, with no original-filtration adaptedness claim.
- Replaced a generic scalar/matrix stability extension with preconditioned dynamics; its nonsymmetric iteration is justified by similarity to a symmetric positive-definite matrix.
- Routed forwarding/const-move items solely to the new value-semantics objective, and Gaussian conditioning/AR forecasting to actual new competencies instead of loosely matching a subsection.
- Improved distractors for distinct occupancy and the normal interval to represent identifiable complement/sample-count and standard-error errors. The list-alias repair uses a concrete list containing two zeroes so a single remove cannot suffice.
- Compared all additions against all 330 originals, each other, six Guided overarching statements/23 parts and six Written statements/subparts. The ledger stores retrieval candidates, including false positives from common code boilerplate. Exact cross-mode prompt duplication is rejected by tests. Lexical similarity is not semantic proof.
- Useful related exercises were retained with distinct demands: opposing two-test evidence versus the Guided single-screen problem; known-variance interval versus Written Student inference; improper convergence versus signed counting cancellation; reciprocal GBM versus Guided logarithmic solution; stationary two-time OU covariance versus Written one-time moments; cubic conditional-martingale representation versus square identities; advanced indexing plus view interaction versus the original basic slice; deep-copy alias graphs versus shallow copy; k-means update/objective versus assignment; Bellman fixed point versus a supplied next-state value. They add assessment behaviours rather than changing only numbers.
- Answer-length screening raises ten new nonblocking candidates. They were individually reviewed: qualifiers distinguish false theorem assumptions/ownership claims, while short numerical outputs naturally differ from explanatory error alternatives. No option was length-padded. These remain learner-calibration signals rather than proof of ambiguity.
