## Working Features

- Home screen with current correct, incorrect, unsure and unseen counts. Answer accuracy is correct / (correct + incorrect) across history; unsure is excluded and an empty denominator displays 0%.
- Quick Practice sessions containing one four-choice question at a time.
- Combined subject, populated subcategory, difficulty and practice-mode filtering.
- Explicit Practice, Review Incorrect, Review Unsure, and Unseen Only modes; All Questions selects every subject without resetting the mode.
- Session sizes of 10, 25 (default), 50 or All, with live eligible/session counts and a disabled Start for empty results.
- Random question order without repeats within a session.
- Random answer order fixed for the duration of each displayed attempt.
- Select/change an answer then Submit, or use Not sure immediately without guessing. Both lock the attempt, reveal feedback and explanations, and require Next.
- Duplicate-submission protection and one persisted attempt per submission.
- Compact session progress and completion summary with Practice Again and Back to Home.
- Persistent attempt history and latest-attempt question status in browser `localStorage`.
- Reset progress at the bottom of History, with explicit confirmation. Successful reset removes only attempts and immediately makes all questions unseen; storage failure keeps history intact.
- LaTeX in question, answer and explanation text through KaTeX, including inline and display math.
- Mobile-width answer controls and desktop keyboard shortcuts.
- Runtime question/reference validation, TypeScript constraints, and automated regression tests.
- Reference browsing by category, populated subcategory and type, with LaTeX statements, assumptions, conclusions, intuition, notation and related concepts.
- Related reference links after submission; returning preserves the active question, shuffled choices, feedback and recorded attempt.
- British English is the content standard; the existing bank/UI were audited and a targeted spelling guard added.
- Install manifest, icons, generated service worker, offline precache, and update prompt in production builds.
- Foreground/connectivity update checks, with activation deferred until the user chooses Update app outside a quiz.
- Repeatable production PWA test (`npm run test:pwa`) covering browser restarts without network/server access and updates without loss of saved attempts.

## Current Architecture

- **Frontend:** React 19, TypeScript, and Vite 6. There is no backend.
- **Routing/navigation:** No routing library or URL routes. The Quick Practice feature switches between home, quiz, completion, and history screens with React state. Bottom navigation contains Practice, History and Reference. Reference is unavailable during an unanswered question; browsing after submission suspends quiz keyboard controls and keeps session state mounted.
- **Shared study metadata:** `src/data/curriculum.ts` defines category/subcategory membership. `src/data/studyMetadata.ts` defines reusable `id`, `category`, `subcategory`, `difficulty`, and optional `tags` metadata.
- **Quick Practice data:** The strict multiple-choice schema and validator are in `src/features/quick-practice/data/schema.ts`. Each record requires exactly four answers and a zero-based correct-answer index.
- **Reference:** Independent schema, validator and static entries are in `src/data/knowledge/`; browsing/filtering lives in `src/features/reference/`. Optional question `knowledgeIds` are validated against that bank. Reference data has no difficulty, answer format or attempt model and is included in the offline bundle.
- **Persistence:** Quick Practice appends immutable attempts to `localStorage` under `quant-pocket.attempts.v1`. There are no accounts, cloud storage, or cross-device synchronisation.
- **PWA/offline:** `vite-plugin-pwa` generates the root-scoped standalone manifest and Workbox service worker. Production builds precache the application, question bank, icons, and bundled KaTeX fonts. `src/hooks/usePwaUpdates.ts` checks for updates on foreground/connectivity events; updates are prompted outside an active quiz. Apple title, touch icon, viewport and status-bar metadata are present.
- **Deployment:** Netlify static-host settings are in `netlify.toml`. `public/_headers` and `public/_redirects` are copied into `dist` for revalidation of entry points, immutable hashed assets, and navigation fallback. Folder upload requires no Git repository or runtime server.
- **PWA verification:** `scripts/verify-pwa.mjs` uses Playwright/Chromium, a temporary production-build copy and an isolated persistent profile. Playwright is development-only.
- **Mathematics:** KaTeX renders text-authored inline and display LaTeX through the shared `src/components/MathText.tsx` component.
- **Question bank:** Human-readable subject files live in `src/features/quick-practice/data/bank/` and are combined and validated by `src/features/quick-practice/data/questions.ts`.
- **Quick Practice logic:** Filtering and attempt status are in `src/features/quick-practice/progress.ts`; mode/filter composition and category-reset rules are in `sessionSetup.ts`; size-limited sampling, transitions and answer shuffling are in `session.ts`; synchronous UI event guards are in `useQuickPracticeSession.ts` (all under `src/features/quick-practice/`).

## Quick Practice

- A session combines category, subcategory, difficulty and mode. The subcategory dropdown appears only for a specific subject and lists populated topics plus All subcategories. Switching categories resets an invalid topic; other filters are retained.
- Size options are 10, 25 (default), 50 and All. The eligible pool is shuffled before taking at most the requested number; short pools are never padded. A subtle count shows eligible questions and actual session size. Empty results disable Start.
- Question order and each sampled question's answer order are randomised at session creation. Answer order remains stable through selection, submission, and rerenders.
- Users may select and change an answer before submitting. Submission locks the choices, records one attempt, and shows plain Correct or Incorrect feedback. Not sure also records one attempt, clears selection and reveals the correct choice without counting as an incorrect guess. Incorrect/unsure feedback identifies the correct answer before the explanation.
- Related references appear only after submission. Back to Quick Practice restores the same submitted question; browsing does not create attempts.
- The app never advances automatically. Next moves to the following question.
- Progress is shown as the current question number over session size, with a thin progress bar.
- Practice ignores prior status; Review Incorrect uses questions whose latest status is incorrect; Review Unsure uses latest unsure status; Unseen Only uses questions with no attempts. These mutually exclusive modes combine with category, subcategory, difficulty and session size.
- Answer rows use the full available width and have mobile-sized touch targets.
- Desktop shortcuts are 1-4 or A-D to select, Enter to submit, U for Not sure, and Enter after submission to advance. Editable fields, modifier combinations, held keys, and unrelated buttons are excluded.
- Completion shows total questions, correct, incorrect, unsure, and answer accuracy, followed by Practice Again and Back to Home. Practice Again reapplies the current filters and size against updated progress.

## Written Problems

Written Problems are planned but are **not implemented**. There is no Written Problems schema, data, screen, navigation item, or placeholder UI.

A future `WrittenProblem` should have its own schema and interaction/progress model. It can reuse the shared `StudyMetadata` fields: `id`, `category`, `subcategory`, `difficulty`, and `tags`. It should not weaken or extend the strict `MultipleChoiceQuestion` contract used by Quick Practice.

## UI / Design Direction

- All user-facing prose uses British English; preserve mathematical notation, proper names and quotations. Authoring rules are in [CONTENT_STYLE.md](../../../CONTENT_STYLE.md).
- Dark mode by default with charcoal backgrounds, light text, muted secondary text, and one restrained accent colour.
- Simple, utilitarian, mobile-first controls with mathematics as the focus.
- No motivational or lifestyle copy and no decorative SaaS-style presentation.
- Avoid gradients, decorative shadows, unnecessary badges, oversized typography, ornamental icons, and animations.
- Prefer plain text, standard lists, dividers, and conventional controls.

## Known Issues / Limitations

- The live PWA's iPhone installation/offline verification is user-confirmed; device/iOS version and detailed real-device update-test results were not supplied. Automated production Chromium offline/update tests supplement this and do not establish long-term iOS storage retention.
- Local changes are not automatically published from this environment. Upload each new `dist` build to the existing quantpocket.netlify.app project, preserving the origin.
- Session setup preferences reset on reload. Subject totals show bank counts, while the eligible/session count reflects all filters.
- The 280-question bank has author review and source spot checks, not independent academic review. [CURRICULUM_MAP.md](../../../CURRICULUM_MAP.md) now maps the bank/reference layer to a canonical syllabus-informed content plan; its topic ratings distinguish remaining gaps from the strengthened Batch A/B foundations, with none strong. Topic coverage and difficulty calibration remain uneven. Review scope/references are in [CONTENT_REVIEW.md](../../../src/features/quick-practice/data/CONTENT_REVIEW.md).
- The reference is an initial authored set, not an independently reviewed or complete curriculum. Advanced gaps include Lindeberg, boundary likelihood ratios, Egorov and pure-birth nonexplosion; some links cover prerequisites only. Details and unlinked IDs are in the [mapping review](../../../src/data/knowledge/MAPPING_REVIEW.md). No concept-level weakness tracking or adaptive recommendations exist.
- Explanations are populated and displayed; full worked solutions and their presentation are still future work.
- History is a basic unpaginated attempt list with no per-topic breakdown, search, individual deletion or export. Bulk reset is implemented.
- Revised questions retain their existing IDs and correct positions; history shows current wording, not content snapshots. Retired `calc-005` attempts remain in history/answer accuracy, but the retired question is excluded from current-bank status counts.
- Active sessions are not restored after refresh or app termination. Submitted attempts remain saved.
- Progress is browser- and origin-local. Clearing site data removes it, and simultaneous sessions in multiple tabs are not transaction-safe.
- Progress on the previous localhost/LAN preview does not transfer automatically to the new HTTPS origin. Future deployments must keep the production origin stable; the localStorage key and attempt format have not changed.
- Family IDs are metadata only; there is no duplicate-family avoidance or parametrised-question tooling.
- Bank tooling covers type/runtime validation, duplicate IDs/prompts, answer shape, taxonomy membership, LaTeX and selected calculation checks. A nonblocking length audit aids editorial review; it cannot establish mathematical correctness or detect semantic duplicates. Complete per-question source provenance is not yet maintained. Batches A and B have item-level reviews ([A](../../../src/features/quick-practice/data/BATCH_A_REVIEW.md), [B](../../../src/features/quick-practice/data/BATCH_B_REVIEW.md)); 42 original mathematical questions remain unlinked, including some with newly available supporting references. The 100 Finance questions currently rely on their self-contained explanations, with no reference links. Conditional variance and cross-isometry still lack direct questions; the CTMC explosion example does not cover the general pure-birth nonexplosion criterion.
- Navigation is state-based rather than URL-addressable, so individual screens cannot be bookmarked or deep-linked.
- The production bundle emits a chunk-size warning (approximately 782 kB for the main JS chunk), largely due to the bundled app and KaTeX assets. This is not currently a functional problem.
- No failing core tests or reproducible Quick Practice interaction bugs are currently known.
