## Project overview

QuantPocket is a mobile-first, local-first web app for studying advanced mathematics and quantitative finance through multiple-choice Quick Practice and a mathematical Reference library. It is a React 19 / TypeScript / Vite 6 PWA using KaTeX and `vite-plugin-pwa`. There is no backend, account system or cloud synchronisation. The interface uses a restrained dark design and British English.

Production is live at **https://quantpocket.netlify.app**. The user previously confirmed iPhone installation and offline use. The current local release, including Finance and other subsequent improvements, **has not been deployed**. Existing deployment and device checks do not establish that the current local release is running on the live site.

## Current application functionality

- Quick Practice combines subject, populated subsection, Easy/Medium/Hard difficulty, and Practice / Review Incorrect / Review Unsure / Unseen Only modes.
- Sessions contain 10, 25 (default), 50 or all eligible questions, sampled without replacement. Question order and four answer choices are randomised; displayed answer order stays fixed during an attempt.
- Selecting an answer then Submit, or choosing Not sure, records one attempt, locks the question and reveals feedback plus its explanation. Next advances explicitly. Desktop shortcuts and session summaries are implemented.
- Home shows current correct/incorrect/unsure/unseen counts. Latest attempts determine review status; full history is retained. Accuracy excludes unsure responses. Confirmed reset clears only Quick Practice history.
- Reference browsing supports category, subsection and type filters. Related references open after submission and return without reshuffling or recording another attempt.
- Production builds precache app data, KaTeX and fonts for offline use. Updates are offered outside an active quiz.

Preserve stable question IDs, existing canonical answers and legacy attempt compatibility. Do not change the storage key or migrate history unnecessarily. Keep the production origin stable to retain user progress.

Navigation uses React state rather than URL routes. Follow the existing architecture, content schema, British-English conventions and mobile interface. Questions are bundled and validated at import/build time. **Written Problems are planned but unimplemented** and must eventually use a separate schema and progress model. Do not commit, push or deploy without explicit authorisation.
